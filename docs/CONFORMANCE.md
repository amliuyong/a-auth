# Agent Auth — Normative Requirements Checklist

> 从 `DESIGN.md` 抽出的**规范性要求**(RFC 2119 风格 MUST/SHOULD/MAY),每条配**验收/测试点**,支撑 DESIGN §10 的"conformance 前移"。
> 这是**实现与测试的契约面**;背景/理由看 DESIGN.md 对应节。`§x` 指 DESIGN.md 的节。
> 状态列:MUST=必须、SHOULD=应当、MAY=可选。阶段列对应 §10 路线图。
> 当前机器校验摘要：total=149，☑=144，◑=2，☐=3。

未完成项的适用性、阻塞类型与跟踪 issue 由
[`requirements.json`](../.github/conformance/requirements.json)
版本化记录；逐行自动化 target、覆盖粒度与 live evidence 由
[`evidence-map.json`](../.github/conformance/evidence-map.json)
版本化记录。CI 会拒绝 ID、计数、状态、分类、exact selector 或引用的
evidence commit/hash 漂移。只有由 CI 实际列出并执行的稳定 selector 才计为
`exact`；尚未建立逐项 selector 的完成行保持 `none`，不以宽泛测试套件冒充覆盖。
历史 live hash 仅作为 `recorded_reference` 留存元数据，不视为可独立重算的 artifact，
也不提升自动化覆盖等级。

## C3 · Refresh / 宽限窗(§2)

| 状态 | # | 级别 | 阶段 | 要求 | 测试 |
|:-:|---|---|---|---|---|
| ☑ | 3.1 | MUST | P0 | refresh 不透明、强制 rotation、复用即全链吊销 | `refresh_rotation_issues_new_tokens` 证明真实 handle 使用可解码为 24 字节的 opaque family 引用 + version，不含 user/client claims、无服务端 family 即拒，并且每次 rotation 返回不同的新版本；`concurrent_refresh_rotation_has_single_winner_then_reuse_revokes_family` 以 8 方 barrier 同步到内存 RefreshStore 的 lease acquisition 入口，关闭 grace 后并发消费同一版本并断言恰一请求成功；`refresh_lease_requests_are_owner_fenced_and_finalize_grace_atomically` 固定生产 Dynamo adapter 以 expected version、未吊销、精确 owner 与未过期 lease 为条件，在同一事务内推进 family version、移除 lease 并写加密 grace；`refresh_reuse_detection_revokes_family` 与并发测试随后复用旧 handle，断言旧值拒绝且当前新值也因全 family 吊销而失效 |
| ☑ | 3.2 | MUST | P0 | 宽限窗仅当 `client_id`+DPoP key(有则)+请求指纹全一致才返回缓存的同一结果;任一不符按复用处理 | `grace_window_same_request_returns_cached` 证明全维度一致时逐字返回同一 access/refresh 且 family 继续可用；`grace_window_request_fingerprint_mismatch_revokes_family` 证明 scope 从缺省改为显式完整集合、或改为另一个仍获授权的 resource，都会拒绝并吊销 rotated family；`grace_window_wire_values_are_decoded_exactly_once` 证明 HTTP form 边界解码后的单 scope `a%20b` 不会在 fingerprint 层再次解码并与双 scope `a b` 折叠；`grace_window_origin_pkce_challenge_is_bound` 证明 code exchange 持久化已验证的 PKCE origin challenge，authority 漂移会改变指纹并吊销 family；`grace_window_client_identity_mismatch_revokes_family` 证明另一个已注册 public client identity 对当前版本只被拒绝、对旧版本重放则吊销原 family；`grace_window_dpop_identity_mismatch_revokes_family` 证明当前版本错 key 不改状态、同 key 重试返回同一缓存、旧版本错 key 无 token 且吊销；`grace_window_reuse_cleanup_failures_are_retriable` 证明 transient/permanent revoke/delete 故障都返回无 token 的 fail-closed 错误，两个 mutation 独立尝试，且部分成功可由后续请求恢复清理 |
