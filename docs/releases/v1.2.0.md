# A Auth v1.2.0 release notes

This source revision adds a single-tenant Kubernetes + PostgreSQL deployment,
a unified enterprise administration console, and the reviewed dependency and
conformance backlog repairs since v1.1.0.

## Compatibility and distribution

Rust workspace and OpenAPI metadata use 1.2.0. Semantic Versioning covers the
HTTP API and public resource-server SDK APIs; deployment configuration and
persisted formats require their runbooks. GitHub provides source archives;
Rust crates remain unpublished. The independently published TypeScript and
Python `agent_auth_rs` SDKs retain version 1.0.2 and their immutable registry
artifacts.

The native release builds matching amd64/arm64 backend and frontend images
on GHCR and Helm chart 0.1.3. Packages remain private and require a package-read
credential. The published GitHub release records their exact digests and
source commit. The pinned 0.1.2 installation example remains a reproducible
historical component selection; select the release's matching digests/commit
when deploying 1.2.0.

## Changes and upgrade guidance

- **Kubernetes + PostgreSQL:** forty-one forward migrations, the complete
  self-hosted persistent port composition, separate token/web and private
  management listeners, mounted ES256/RS256 signing with rotation, portable
  SMTP/OIDC transports, durable governance/event/SMTP/SSF workers and maintenance
  Jobs. Secure containers, Helm defaults, NetworkPolicy examples, installation,
  backup/restore and upgrade procedures are included. SaaS and multi-Region
  Kubernetes deployment are outside this profile. Start with the
  [installation guide](../KUBERNETES_INSTALL.md),
  [runtime configuration](../POSTGRES_RUNTIME.md) and
  [delivery ledger](../KUBERNETES_DELIVERY.md).
- **AWS upgrade:** both HTTP runtime roles need transaction snapshot reads of
  SCIM aliases through `dynamodb:TransactGetItems` on the Users table. Review
  the CDK IAM diff and follow local approval requirements before updating an
  existing AWS deployment. The native release's protocol evidence qualifies
  its EKS/PostgreSQL candidate.
- **Administrator console:** shared navigation and enterprise styling,
  consistent tables, pagination and detail views across supported workflows.
  Authentication and action-specific role checks remain enforced.
- **MCP example:** migrate `mcp-auth` to 1.0.0-beta.1 and official MCP 2 server
  and Express/Node adapters, with current provider metadata checking. Actual
  controlled TLS/JWKS/signed-token tests verify a protected tool call and
  issuer, audience, signature, expiry, subject, scope and sender-bound-token
  rejection. Full-client natural-expiry refresh with this prerelease is NOT_RUN;
  historical client/refresh results remain tied to the original 0.2.0 fixture.
  See [MCP interoperability](../MCP_INTEROP.md).
- **Dependencies and regression checks:** deliver the six pending Dependabot
  updates, patch affected body-parser, ip-address and Zod dependencies, and
  synchronize the PostgreSQL expiry regression with actual row-lock release
  after asynchronous rollback. SDK public versions remain unchanged.
- **Historical conformance failures:** #136's unknown-parameter module now
  passes in fresh official evidence; #141's cancelled/configuration-invalid
  attempt is superseded by successful protected and scheduled runs. Prior
  failures remain recorded rather than reclassified as passes.

## Security and acceptance limits

The official braces advisory was withdrawn upstream on 2026-10-23. Root
Markdown tooling and updated SDK/example complete installed audits report
zero current findings; braces remains 3.0.3, with no downgrade, replacement,
vendor patch or suppression. Historical v1.1.0 audit failures remain historical.
See [dependency dispositions](../DEPENDENCY_PATCHES.md).

CDK 2.273.0 still bundles minimatch 10.2.5 under
[GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249).
Its complete audit reports two Moderate nodes for one underlying advisory.
The latest upstream CDK also retains an affected bundled dependency, and npm
override does not replace that bundle. No downgrade, vendor patch or audit
suppression is applied. This is an infrastructure build-tool dependency;
CDK callers consume repository-controlled patterns and do not enable the
advisory's optimization level 2. It is absent from the native/Rust runtime.
The advisory remains unpatched and is not described as fixed.

Candidate promotion requires exact reviewed-source CI, immutable image/chart
readback, installed source identity and a fresh signed hosted OIDF Basic OP
code-flow plan plus 13 selected project-owned RFC 9700 regressions against the
same EKS/PostgreSQL candidate. Publication records that evidence separately
from the historical #142 component qualification and AWS baseline. The existing
14 owner-approved non-PASSED bindings remain limited by #67's original expiry;
no exceptions are expanded or renewed.

A source release and passing protocol gate do not authorize production restore
promotion. Stale-backup rollback can resurrect revoked authority; complete
external-effect/authority reconciliation is not implemented. The isolated
restore clones remain `HOLD_NO_RELEASE` with HTTP deployments at zero replicas.
The [restore disposition](../KUBERNETES_RECOVERY.md) documents the boundary.
Project tests are not standards-body certification. FAPI, OpenID Federation,
blanket RFC 9700 certification and Kubernetes SaaS remain explicit non-claims.
Lambda Function URLs remain prohibited.
